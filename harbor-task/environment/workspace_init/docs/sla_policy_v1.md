# 跨境清结算平台 SLA 赔付与生产变更管理制度 (v1.0)

> 版本：v1.0（如合规部或变更委员会在内部邮件发布正式勘误或临时生效通知，以最新生效通知为准）

## 一、故障认定与日志清洗口径
1. **统计时间口径**：所有对外审计与赔付计算均统一采用 **东八区 (`UTC+8`)**。若原始日志时间戳带 `Z` 或其他时区偏移，必须先统一折算至 `UTC+8`。
2. **测试商户剔除**：`merchant_id` 以 `TEST_` 开头的沙箱/压测商户不纳入生产 SLA 统计与赔付。
3. **请求去重与重复扣款风险认定**：
   - 同一个 `tx_id` 若在网关日志中出现多次重试记录，单笔交易的最终延迟与状态**以时间戳最晚的一次尝试为准**；
   - **特殊风控规则（重复扣款风险）**：如果同一 `tx_id` 在早先某次尝试中已经出现 `status == "SETTLED"`，随后又出现后续尝试（无论后续成功或失败），则该笔交易的最终结算状态仍计为有效结算，但必须将其 `tx_id` 标记为 **重复扣款风险 (`DUPLICATE_DEBIT_RISK`)** 并在审计报告与批次统计中列明。
4. **违约延迟判定**：仅针对结算日期为 `2026-11-24 (UTC+8)` 的正式商户交易，在去重后若满足：
   - 最终状态为 `TIMEOUT` / `504` / `FAILED`，**或**
   - 最终 `latency_ms > 对应商户等级的 SLA 延迟阈值（严格大于）**
   则该笔交易计为 **SLA 违约交易 (`breached`)**。

## 二、基础赔付率与商户等级（v1.0 初始值）
| 商户等级 (`tier`) | SLA 延迟阈值 | 单笔违约赔付比例（按折算后 CNY 结算金额） | 单批次赔付上限 |
|---|---|---|---|
| `STD`（标准商户） | `1500 ms` | `0.5%` (`0.005`) | 无上限 |
| `VIP_T1`（核心 VIP 商户） | `1000 ms` | `1.5%` (`0.015`) | 无上限 |

- **批次赔付金额计算公式**：对某个 `batch_id` 内所有被判定为 `breached` 的交易，逐笔计算 `amount_cny * penalty_rate` 求和（若存在单批次上限，则取 `min(求和结果, 批次上限)`），最终保留 **2 位小数**（四舍五入 `ROUND_HALF_UP`）。
- 币种折算：外币需按公司财务部/合规部最新发布的当期固定汇率折算为 `CNY`（保留 2 位小数或先汇总再四舍五入，以通知说明为准）。

## 三、生产变更发布规范（v1.0 初始值）
1. 常规及紧急变更均须关联修复分支合入 `main` 后的实际 Commit SHA 及技术定位证据。
2. **日终清结算冻结窗口（v1.0）**：每日 `20:00 - 22:00 (UTC+8)` 禁止执行 `risk-engine` 与 `settlement-worker` 生产发布。
3. 故障节点处置：CMDB 中仅允许隔离经监控/Trace 证实异常的节点，严禁误摘除健康主节点或数据库主节点。
