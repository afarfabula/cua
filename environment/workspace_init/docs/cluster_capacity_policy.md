# 季度 H100 集群物理约束与算力治理规范

## 一、物理基础设施与保护区红线
1. 集群共 6 台机柜 `R0–R5`，每台机柜竖直分布 4 个物理槽位（`Bay 0` 在最底层至 `Bay 3` 在最顶层），每个槽位配备 `4 × H100`（整机柜 16 卡）：
   - **`R0`（Spine-A / Zone-A，24kW 上限）**：承载线上实时推理服务 `PROD-ONLINE-INFERENCE`（24H 独占 `Bay 0–3`），**任何时候严禁改动或迁移**。
   - **`R1`、`R2`（Spine-A / Zone-A，22kW 上限）**：配备本地高速 NVMe 存储池，无 RDMA 专网。
   - **`R3`（Spine-A / Zone-B，20kW 上限）**：普通对象存储，无 RDMA 专网。
   - **`R4`（Spine-B / Zone-B，22kW 上限）**、**`R5`（Spine-B / Zone-B，24kW 上限）**：配备低延迟 RDMA 专网，适合重 AllReduce 通信的大规模训练。
2. 各机柜在 `DAY (09:00–21:00)` 与 `NIGHT (21:00–09:00)` 两个独立供电统计窗口内的峰值功耗总和均不得超过对应机柜 `cap_kw`。
3. 同一物理槽位不可在重叠时段安排两个任务；但可将互相配合的 `DAY_ONLY` 与 `NIGHT_ONLY` 任务分时复用同一物理槽位。

## 二、预算准入与冗余申请甄别
1. 分配范围（`R1–R5`）月度总预算硬上限为 **`$138,000`**：
   - 班次基础费：`DAY_ONLY = $3,800 / bay / 月`、`NIGHT_ONLY = $2,400 / bay / 月`、`24H = $6,200 / bay / 月`。
   - RDMA 专网附加费（`R4/R5` 开启 RDMA）：`+$400 / bay / 月`。
   - 跨区数据 egress 费：需要 Zone-A 本地高速盘的实时任务若落入 Zone-B，每槽加收 `+$4,000 / bay / 月`。
2. 只有在 FinOps 台具备有效 `ACTIVE` 预算 PO 且未在历史归档中重复建单的团队才允许占用 H100 生产资源；不符合条件或重复申请的工单应当清零槽位并执行 `Defer`（挂起），否则将计入无效占卡处罚并拉低集群总效用。

## 三、集群热力学、互联与存储耦合诊断以及 Staging 仿真配额
1. 为避免无效试错占用压测集群，**Staging 仿真演练全天最多只允许运行 4 次**，请结合热力图遥测与各团队沟通定位物理规律。
2. 即使表面功率墙与总预算均未超标（`FEASIBLE`），机房内的散热结构、交换机互联域与本地存储总线耦合仍会显著折损真实有效算力。具体哪些机位、带宽域或存储共享组合会触发衰减（包括热告警区与 IO 队列饱和），请通过 **Staging 仿真指标** 与 **机柜热力图遥测（`/api/simulations/heatmap.png`）** 结合团队工单/历史归档自行交叉诊断。排布优化应尽量使集群真实有效算力效用与月度成本效率同时达到最高。

## 四、团队协商与正式签发
1. 当有效业务团队原始申请总数超出 `R1–R5` 物理槽位上限时，请在 **Team Negotiation Desk (:8082)** 结合各团队负载特点提出具体补偿条件（如 RDMA 专网、单 Spine 零降频、优先 IOPS 与夜间/日间分时错峰），达成新配额共识后再完成排布与 `Sign-off`。
2. 最终排布与签收完成后，必须在 **FinOps & Release Portal (:8083)** 执行正式签发落库，并将本地交付件写入 `/workspace/output/`。
